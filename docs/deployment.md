# Deployment

| Part     | Host                     | Config                 | Deploys                                    |
| -------- | ------------------------ | ---------------------- | ------------------------------------------ |
| Frontend | Vercel                   | `frontend/vercel.json` | Every push to `main`, preview for every PR |
| Backend  | Render (Docker, free)    | `render.yaml`          | Pushes to `main`, after CI checks pass     |
| Database | MongoDB Atlas (M0, free) | Render env var         | Not deployed, data lives in Atlas          |

The browser only talks to Vercel. Vercel forwards every `/api/*` request to the backend on Render, so the app stays on one domain (no CORS or cookie issues) and the frontend code calls `/api/...` exactly as in local development.

## One-time setup (maintainer)

### 1. MongoDB Atlas

1. Create a free **M0** cluster, region Frankfurt (`eu-central-1`) to sit close to Render.
2. **Database Access**: add a user with a long generated password and the `readWrite` role.
3. **Network Access**: allow `0.0.0.0/0`. The free Render plan has no fixed outgoing IP, so the password is what protects the database.
4. **Connect → Drivers**: copy the connection string and add the database name: `mongodb+srv://<user>:<password>@<cluster>/gate-parking?retryWrites=true&w=majority`.

### 2. Render (backend)

1. **New → Blueprint**, pick this repository. Render reads `render.yaml`.
2. When asked, paste the Atlas connection string as `MONGODB_URI`. `JWT_SECRET` is generated by Render.
3. Wait for the deploy, then open `https://<service>.onrender.com/api/health`. It must return `{"status":"ok","db":"up"}`.
4. If Render gave the service a URL other than `gate-parking-backend.onrender.com`, put the real one in `frontend/vercel.json`.

### 3. Vercel (frontend)

1. **Add New → Project**, import this repository.
2. **Root Directory**: `frontend`. Framework preset: Vite. Leave the build command and output directory (`dist`) at their defaults.
3. Deploy, then open the Vercel URL and check that `<vercel-url>/api/health` answers through the rewrite.

## Day to day

- Merging a PR into `main` deploys both parts. Nobody deploys by hand.
- Every PR gets a Vercel preview link. Previews use the production backend and database, so do not test destructive actions there.
- Secrets live only in the Render dashboard, never in the repository.

## Known limits of the free plans

- **Cold start**: the Render backend sleeps after 15 minutes without traffic, and the first request then takes up to a minute. Open `/api/health` a few minutes before a demo.
- **Atlas M0** has 512 MB of storage and no automatic backups.

## Backup and restore

Needs the [MongoDB Database Tools](https://www.mongodb.com/docs/database-tools/) and the Atlas connection string:

```bash
mongodump --uri "$MONGODB_URI" --out backup-$(date +%F)
```

```bash
mongorestore --uri "$MONGODB_URI" --drop backup-YYYY-MM-DD
```

`--drop` replaces the existing collections, so only restore when you mean to overwrite the live data. Keep backups out of the repository.
